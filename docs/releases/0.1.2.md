# CowBot 0.1.2 — Automatic updates

CowBot 0.1.2 adds automatic updates: the desktop app now checks GitHub Releases
at launch, shows a banner when a newer version exists, and installs it in-app.
It also includes a code-simplification pass across the workspace.

## Highlights

- **Automatic updates.** Settings → About has a "Check for updates
  automatically" toggle (on by default), a manual check, and download/install
  progress. Update checks send no workspace data and can be turned off. See
  [ADR-0018](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0018-desktop-auto-updates.md).
- **Signed update channel.** Every `v*` tag publishes a `latest.json` manifest
  and minisign-signed updater artifacts, so updates are verified even though the
  installers themselves are not code-signed.
- **Installing waits for running crews.** Installing is refused while a crew
  runs, so a task is never interrupted mid-run.
- **Simplification pass.** Duplicate validation was removed across
  `cowbot-core`, `cowbot-package`, `cowbot-store`, and `cowbot-client`, the
  service and agent event publishing were simplified, and unused dependencies
  were dropped.

## Upgrade

> **Users on 0.1.1 and earlier must install 0.1.2 manually once.** Those
> versions contain no update code, so they cannot see this release. After
> 0.1.2, updates are offered in-app.

- **Windows (NSIS setup):** updates in-app from 0.1.2 onward.
- **Windows (MSI):** install the new NSIS setup or MSI manually.
- **macOS (from the DMG):** updates in-app. Builds remain unsigned and
  un-notarized, so macOS may ask you to allow CowBot again after an update.
- **Linux (AppImage):** updates in-app.
- **Linux (deb):** download and install the new package.

## Compatibility

- Workspaces, `config.json`, and `.cowpkg` packages from 0.1.1 continue to work.
- No schema changes.

## Known limitations

- Local/offline single-user mode only: no server, remote sessions, or
  multi-user workspaces.
- Sequential Planner → Coder → Reviewer crews; no hierarchical orchestration.
- No background wake/re-entry scheduler for delegated assignments (ADR-0006).
- No streaming responses, retries, rate limiting, or token accounting.
- The subprocess sandbox is not OS-level isolation.
- Builds are unsigned (updater signatures are separate from code signing).

## Release engineering note

`v0.1.2` was re-tagged before publishing. The first run built macOS with only
the `dmg` bundle, which does not emit the `.app.tar.gz` updater archive, so the
manifest job failed. [#57](https://github.com/BerryUIKI/CowBot/pull/57) builds
`app,dmg` on macOS. No artifacts were ever published from the failed run.
