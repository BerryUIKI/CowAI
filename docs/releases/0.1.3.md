# CowBot 0.1.3 — Assignment scheduling, CLI configuration, and model discovery

CowBot 0.1.3 rounds out Phase 1. The assignment runtime gains a scheduler with
wake/re-entry and cross-root concurrency, the CLI gains a configuration file and
channel/message commands, and the desktop provider editor becomes vendor-first
with endpoint model discovery and several models per provider.

## Highlights

- **Assignment scheduler.** `cowbot-service::AssignmentScheduler` is now the
  single dispatch path for agent work. It consumes queued roots and resumed
  parents, re-enters a waiting parent with its children's outputs, runs
  independent roots concurrently (default 4), keeps the assignments of one root
  serialized, and fails a dependent task whose prerequisite did not complete.
  See [ADR-0019](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0019-assignment-scheduler.md).
- **CLI configuration.** An optional `cowbot.toml` supplies the database, model,
  base URL, approval policy, and concurrency limit. Lookup is `--config`, then
  `COWBOT_CONFIG`, then `./cowbot.toml`; command-line and environment values
  override the file. API keys stay in environment variables and are never read
  from the file. See [ADR-0020](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0020-cli-configuration-and-channels.md).
- **CLI channels and messages.** `cowbot channel list|create` and
  `cowbot message list|post` work against the local workspace, and
  `cowbot run --channel <id>` stores the crew's tasks in a channel.
  `--concurrency` overrides the scheduler limit for one run.
- **Vendor-first providers.** Adding a provider now starts from a searchable
  vendor catalogue grouped into model vendors, platforms and relays, cloud
  providers, and local runtimes. `Custom` is the first entry. Protocol is a
  dropdown inside the form, and changing it keeps the name, base URL, and model
  you entered. See [ADR-0021](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0021-vendor-first-model-providers.md).
- **Model discovery and multiple models.** **Fetch models** lists the endpoint's
  catalogue for the OpenAI Chat, Anthropic, and Responses protocols. One
  provider can hold several models with one active model, so switching models
  does not require re-entering the key. Providers saved before this change load
  with their current model as the only entry.
- **Documentation and site.** New ADRs 0019–0021, archived release notes under
  `docs/releases/`, updated user and CLI guides, and the GitHub Pages landing
  page.

## Upgrade

- **Windows (NSIS setup):** updates in-app from 0.1.2.
- **Windows (MSI):** install the new NSIS setup or MSI manually.
- **macOS (from the DMG):** updates in-app. Builds remain unsigned and
  un-notarized, so macOS may ask you to allow CowBot again after an update.
- **Linux (AppImage):** updates in-app.
- **Linux (deb):** download and install the new package.

Existing local databases, `config.json` files, and `.cowpkg` packages from
0.1.2 continue to work; there are no schema changes. The desktop adds the
current model to each saved provider's model list on first load.

CLI defaults are unchanged unless a `cowbot.toml` is present. `--model` and
`--approval` now fall back to the file when omitted, so scripts that relied on
the built-in defaults should pass the flags or leave the file absent.

A task whose prerequisite task failed or was cancelled now fails with a typed
reason instead of running without that context.

## Checksums

The release workflow publishes SHA-256 sums alongside the GitHub Release assets.

## Known limitations

- Local/offline single-user mode only: no server, remote sessions, or
  multi-user workspaces.
- Sequential Planner → Coder → Reviewer crews; no hierarchical orchestration,
  DAG workflows, or agent-facing delegation tool.
- No streaming responses, retries, rate limiting, or token accounting.
- The subprocess sandbox is not OS-level isolation.
- Builds are unsigned; updater signatures are separate from code signing.
- Workspace deletion and renaming are not available in the desktop UI.
