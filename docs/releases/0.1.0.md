# CowBot 0.1.0 — local/offline MVP

The first public preview of CowBot: a local-first multi-agent workspace written
in Rust, with a Tauri desktop shell, a CLI, and SQLite-backed history. Everything
runs on your machine; an OpenAI-compatible endpoint is optional and the offline
mock model works without one.

## Highlights

- **Desktop app** — first-run onboarding, switchable model providers, channels,
  task creation with assignment/run history, and approval handling.
- **CLI** — `cowbot init`, `run`, `tools`, `export`, and `import`, with persisted
  history and selectable approval policies (`ask`, `safe-auto`, `plan-only`,
  `trusted`).
- **Sequential agent crew** — Planner → Coder → Reviewer over a local event bus,
  with tool calls routed through a subprocess sandbox and risk-based approvals.
- **Model providers** — any OpenAI-compatible endpoint (OpenAI, DeepSeek, Ollama,
  …), plus an offline mock provider for dry runs and tests.
- **Portable workspaces** — `.cowpkg` ZIP packages with per-file SHA-256
  checksums for export and verified import.

### Install

- **Windows:** run the NSIS installer or the MSI.
- **macOS:** open the DMG and drag CowBot into Applications.
- **Linux:** `sudo apt install ./CowBot_0.1.0_amd64.deb`, or
  `chmod +x CowBot_0.1.0_amd64.AppImage && ./CowBot_0.1.0_amd64.AppImage`.

## Compatibility

- First public release; there is no earlier database to migrate.
- Desktop state lives in the platform app-data directory (`cowbot.db` and
  `config.json`); the CLI database defaults to `cowbot.db` in the working
  directory and can be set with `--db` or `COWBOT_DB`.
- The desktop works offline with the mock model; connect a provider in Settings
  to use a real model.
- Building from source requires a stable Rust toolchain. The desktop frontend
  requires Node.js 22.13+ and pnpm 11.

## Known limitations

- Local/offline MVP only: no REST/WebSocket API, no remote `cowbot-client` mode,
  and no desktop workspace import/export.
- The subprocess sandbox runs commands with the current user's permissions.
  Approval policies are guardrails, not OS isolation; treat model-generated
  commands as untrusted.
- Streaming responses, retries, rate limiting, and token accounting are not
  implemented.
- Sequential crews only; hierarchical orchestration, agent long-term memory, and
  a wake/re-entry scheduler for delegated assignments are future work.
- Docker/WASM sandbox backends are not implemented.
- The CLI reads flags and environment variables only; config files and channel
  collaboration from the CLI are not implemented.
- No code signing, notarization, or auto-updates.
