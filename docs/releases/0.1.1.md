# CowBot 0.1.1 — Phase 1 complete

CowBot 0.1.1 completes the local/offline MVP (Phase 1). It adds three model API
protocols, a reworked desktop settings experience, workspace creation and
transfer, and the first user guide.

## Highlights

- **Three model protocols.** Connect OpenAI Chat Completions, Anthropic Messages
  (Claude and Claude Code-compatible relays), or OpenAI Responses (Codex-style)
  endpoints. Protocol-first presets fill the endpoint, custom base URLs and
  models are supported, and the connection test uses the selected protocol.
  Existing `config.json` providers load as OpenAI-compatible.
- **Redesigned Settings.** Settings moved from the main navigation to the
  sidebar footer and is organized into Model, Team, and Workspace sections. The
  provider editor selects a protocol first, then a preset, and reports test
  results in place.
- **Workspaces you can move.** Create empty workspaces, export the active one as
  a `.cowpkg` package, and import packages as new local databases. Each
  workspace has its own database; switching restarts CowBot, and all workspace
  changes wait for running tasks to finish.
- **User guide.** `docs/USER_GUIDE.md` covers installation, onboarding, model
  setup, workspaces, tasks, approvals, workspace transfer, CLI use, backups, and
  troubleshooting.
- **Build tooling.** The desktop frontend uses pnpm with a committed lockfile;
  CI and the release workflow install with `--frozen-lockfile`.
- **Phase 1 complete.** Milestones 1.1–1.7 and the Phase 1 exit criteria are met.

### Install

- **Windows:** run the NSIS installer or the MSI.
- **macOS:** open the DMG and drag CowBot into Applications.
- **Linux:** `sudo apt install ./CowBot_0.1.1_amd64.deb`, or
  `chmod +x CowBot_0.1.1_amd64.AppImage && ./CowBot_0.1.1_amd64.AppImage`.

## Compatibility

- Workspaces and `config.json` from 0.1.0 continue to work. Providers saved
  before protocol selection existed are treated as OpenAI-compatible.
- New workspaces use separate SQLite databases under the app data directory
  (`workspaces/<uuid>.db`); the default remains `cowbot.db`.
- Creating, importing, and switching workspaces restart the app.
- `.cowpkg` packages never include credentials or API keys.

## Known limitations

- Local/offline single-user mode only: no server, remote sessions, or
  multi-user workspaces.
- Sequential Planner → Coder → Reviewer crews; no hierarchical orchestration or
  DAG workflows.
- No background wake/re-entry scheduler for delegated assignments (deferred by
  ADR-0006).
- No streaming responses, retries, rate limiting, or token accounting.
- The subprocess sandbox is not OS-level isolation.
- Builds are unsigned and do not auto-update.
- Workspace renaming/deletion and a standalone agent editor are not part of
  0.1.x.
